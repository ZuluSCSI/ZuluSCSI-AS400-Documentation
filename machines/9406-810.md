Use **v2026.11.17 or later**. It is the first release with all the fixes this machine needs:

## Working configuration

```ini
[SCSI]
System = AS400_PPC
MaxSyncSpeed = 10           ; 20 MB/s wide; at 40 MB/s, DATA OUT fails parity (#1058)

[SCSI3]
IMG0 = "LOADSRC.img"        ; no "_" in the name: digits after "_" are parsed as the block size
AS400_DiskProfile = "53P3239"
AS400_DiskSerialNumber = "00100001"
PrefetchBytes = 4160
```

- `AS400_DiskSerialNumber` is optional for a single disk. Without it, the disk reports the serial captured from the real drive, `00044872`. With two or more disks on the same profile, give each a different value.
- Start from a blank image. See [Changing the serial](#changing-the-serial) below.

## SCSI behavior of this machine

Observed in `zululog.txt` with debug logging on:

- **Bus negotiation.** The IOA sends WDTR for 16-bit transfers, then SDTR with period factor `0x0C` (50 ns, Fast-20) and offset 60. ZuluSCSI answers with offset 15 and logs the rate as `42 MB/s`; this page calls it 40 MB/s. With `MaxSyncSpeed = 10` it answers period factor `0x19` (100 ns, Fast-10), which gives 20 MB/s on the wide bus.
- **Identification.** The host reads the standard INQUIRY (allocation lengths `0x3C` and `0xFF`) and VPD page `0x03`. It does not read pages `0x80` or `0x83`, so the serial at offset 36 of the standard INQUIRY is the only one it sees.
- **Commands used during a LIC install:** TEST UNIT READY, REQUEST SENSE, INQUIRY, REPORT LUNS, START STOP UNIT, READ CAPACITY, MODE SENSE(6), MODE SELECT(6), READ BUFFER, WRITE BUFFER, READ(10), WRITE(10), WRITE SAME(10), and the AS/400 vendor commands Skip Read(10) (`0xE8`) and Skip Write(10) (`0xEA`).
- **Linked Skip commands.** Skip Read and Skip Write are always sent with the link bit set and are followed by the READ(10) or WRITE(10) they apply to. The target must answer with INTERMEDIATE status and then LINKED COMMAND COMPLETE. Without the STATUS phase, the IOA rejects the message.
- **Volume of a full install.** The successful install with debug logging on ran for about 7 hours and logged 26,780 commands: 14,318 READ(10), 9,362 WRITE(10), 2,097 WRITE SAME(10), 200 Skip Write and 6 Skip Read.
- **FORMAT UNIT.** The host sends FORMAT UNIT when it sees a disk serial it does not know. ZuluSCSI completes it at once and does not change the image.

## Known issues and SRC codes

| Symptom | Cause | What to do |
|---|---|---|
| SRC `A60B0266` during "initialize disk" | Firmware older than v2026.11.17 skips the STATUS phase of linked Skip Write commands, and the IOA answers with MESSAGE REJECT | Update the firmware |
| SRC `43263100` at the first write | At 40 MB/s almost every DATA OUT from the host fails the parity check ([#1058](https://github.com/ZuluSCSI/ZuluSCSI-firmware/issues/1058)). Reads are not affected | Set `MaxSyncSpeed = 10` |
| "An unrecoverable error occurred", error code 62 ("one of the subtasks is ending abnormally") during the LIC install | The serial was changed on an image that already held an install. The host formatted the "new" unit, but the old data stayed in the image | Recreate the image as a blank file |
| "A disk could not be found to be the load source" | No SD card in the board | Insert the card and power-cycle the board |
| Log warning `file LOADSRC.img is not contiguous` | The image file is fragmented on the card | Works, but with higher read latency. Create the image on a freshly formatted card to get a contiguous file |

### Parity errors at 40 MB/s

Without `MaxSyncSpeed`, ZuluSCSI accepts the host's Fast-20 offer. In the test session that followed, 63 of 71 DATA OUT transfers failed with CHECK CONDITION, ABORTED COMMAND, ASC `0x47` (SCSI PARITY ERROR), including every WRITE(10). All 108 DATA IN transfers completed with GOOD status. The host renegotiated the same rate after each error, retried 17 times, and stopped the install with SRC `43263100`.

At 20 MB/s, the same board, cable and machine completed more than 11,000 DATA OUT transfers without a parity error. The firmware from May 2026 shows the same failure at 40 MB/s. Details and log excerpts are in [#1058](https://github.com/ZuluSCSI/ZuluSCSI-firmware/issues/1058).

### Changing the serial

OS/400 records a disk by its serial. With `AS400_DiskSerialNumber` changed on an image that already holds a LIC install:

1. The host sees an unknown unit, sends MODE SELECT and FORMAT UNIT, and then waits about 45 minutes, polling with TEST UNIT READY, as it would for a real drive.
2. ZuluSCSI returns GOOD for the FORMAT UNIT but leaves the image as it was, so the old install is still there.
3. The LIC install then stops with error code 62, although every SCSI command in the log completed with GOOD status.

With a blank image and the same serial, the install completes.
